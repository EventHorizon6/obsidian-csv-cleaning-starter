Check a messy CSV before you import it

Most CSV import problems come from five things you can check yourself. Here is how to spot each one, a worked example on a synthetic file, and where to get it checked if you would rather not do it yourself.

Five checks before you import

  1. Text that would run as a formula. A cell that is not a plain number but begins with =, +, - or @ can be run as a formula when the file is opened in a spreadsheet. Search each text column for those first characters.
  2. Dates that can be read two ways. 03/04/2025 is either 3 April or 4 March. If some value in the column has a first or second part above 12, the order can be proven. If none does, decide the order yourself instead of letting the importer guess.
  3. Duplicates versus conflicts. Rows that repeat exactly are easy to see. Rows that share an email or ID but disagree elsewhere are a decision, not something to delete. Sort by the key column and compare neighbouring rows.
  4. Placeholders and blanks. "N/A", "null", "-" and an empty cell can mean different things to an importer. Filter each column for them and decide what each should become.
  5. Rows with the wrong number of cells. A stray comma or line break inside a value shifts every cell after it. Open the file in a plain text editor and look at rows that are longer or shorter than the header.

A worked example (synthetic data, not a client file)

An eight-row synthetic CSV contained three duplicate groups: one group of exact repeats and two groups of records that shared a key but disagreed elsewhere - six rows in the two conflict groups. The same file also held formula-like text, ambiguous numbers, placeholder text, a repeated row and an empty cell.

Nothing was deleted. Each finding was listed with its spreadsheet row number so a person could decide what to keep. A cell with no flag is not a guarantee of business correctness.
